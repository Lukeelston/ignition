# Ignition — engine sound workbench

Luke requested a parallel program to Syrinx Studio, with both real-engine and sci-fi sound design and many controls. Build a standalone sibling in `Projects/engine-generator`; do not modify Syrinx.

Builder choices: name Ignition, local Chrome UI, JavaScript DSP shared between an AudioWorklet and offline render worker, Python standard-library loopback server. No runtime third-party dependencies, remote calls, accounts, or sample downloads. Procedural sound design rather than a thermodynamic simulator or a licensed vehicle recording library.

The bench offers V8, inline-six, racing four, V-twin, diesel, jet turbine, ion drive, and heavy freighter starting points. RPM, throttle/load, cylinder count and firing style define the movement. Exhaust resonance, body, rasp, intake noise, mechanical whine, turbo, roughness, sub and reactor modulation define the sound. Live ignition, hold-to-rev, automated rev, mute/stop, scope, and tachometer give immediate feedback. Keyboard and mobile controls work. No autoplay.

Export 48 kHz 24-bit mono WAV, 2–30 seconds, with steady, rev, sweep, and through-gears trajectories. Save/load versioned JSON patches with repeatable seeds. Audio remains bounded, controls are smoothed, and start/end ramps prevent clip edges. Exports run off the UI thread. Validate imported patches before modifying the current patch.

Visual direction: a motorsport instrument bench with a large analogue tachometer, muted navy enamel (#172d3b), silver face (#e9edf0), warm white (#fafbf9), petrol blue (#28758a), yellow needle (#f5cc4e), and warning red (#cb493d). Use Bahnschrift for instruments/headings and Segoe UI for controls. Single memorable dial, a preset rail, and grouped control strips; no decorative card grid. Responsive stacking at narrow widths. Visible focus, labelled controls, live status, reduced-motion support.

Verification: deterministic DSP tests; finite/bounded audio across extreme controls and all presets; physically correct four-/two-stroke firing rate; changing RPM and load changes the signal; valid 24-bit WAV headers and samples; malformed patch rejection. Actual Chrome smoke test must exercise AudioWorklet playback and capture its signal, controls, stop/restart, patch roundtrip, worker export/download, and mobile layout. Inspect screenshots. Perceived realism and physical speaker output require Luke's ears and remain unverified. Clean up all test servers and browser processes.
