# V8 sound refinement

Luke requested continued sound improvements, permitting free assets, and selected a V8 muscle car as the priority. This is a refinement of the existing browser and ESP toy. Implementation choices below are the assistant's.

## Approach and design

Keep continuous procedural synthesis: recorded loops would need several matched RPM/load recordings, clean loop points and additional storage. A bank-aware exhaust model fits the existing ESP audio path and responds to every RPM/load value. No third-party recordings or source code are being incorporated.

The current V8 varies the amplitude of one equal-spaced pulse stream. Replace that V8 voice with two independently resonating, saturating exhaust banks, routed in Chevy 1-8-4-3-6-5-7-2 order. Each bank receives unequal intervals although total combustion remains evenly spaced. Short, rounded blowdown pulses excite low body and upper exhaust resonances. Load opens the exhaust bandwidth and strengthens its bark. Existing body/exhaust/rasp controls shape this model. Preserve the acceleration-only stochastic texture, idle-only crank flutter, patch format, controls, drive model and other engine families.

Sources: [Speedway's distributor instructions, firing order and cylinder diagram](https://content.speedwaymotors.com/DigitalAssets/assets/charts/2896501_INS_2024_1.pdf); [W3C-hosted RBJ biquad equations](https://webaudio.github.io/Audio-EQ-Cookbook/audio-eq-cookbook.html). These inform an original implementation, not copied assets.

Listening refinement: Luke liked the first revision's lower rumble but described the top as a sine wave changing pitch. A spectral probe isolated the exhaust itself, rather than the optional gear-whine layer, as the dominant source. Near-equal mono bank mixing suppressed the bank rhythm. Use a near-tailpipe perspective (opposite bank at 0.32 relative gain), and guard against a single firing harmonic exceeding 55% of the isolated loaded voice's energy at 3,600/6,000 RPM. This is a sound-design acceptance criterion, not a physical engine specification. The first revision measured 70% at 3,600 RPM. Free recordings were researched; none is incorporated in the shipped sound.

## Implementation and verification

1. Preserve baseline renders and measure steady/load response at 16 and 48 kHz. Add regressions for the observable acoustic goals: load must increase upper harmonic content, not merely loudness; upper-RPM voice must retain useful level. Keep existing no-hiss, no-driving-flutter and firing-count checks.
2. Implement bank filters/voice in `web/engine.js`, then equivalent allocation-free DSP in `firmware/ignition/v8_exhaust.h` and integrate in `core.h`. Retune the V8 preset only as needed; regenerate `presets.h`.
3. Add a repeatable before/after demonstration covering idle, throttle blips, acceleration, sustained RPM and lift-off. Match comparison levels to avoid mistaking loudness for quality. Produce both browser-rate and actual 16 kHz firmware renders.
4. Run the complete Node tests, native core tests, new native/browser sound measurements, ESP32-S3 compile, and real Chrome standalone/worklet smoke checks. Regenerate `Ignition.html`, document results, commit and update the existing GitHub repo after verification.

## Review focus

- Avoid random idle/static regressions and periodic high-RPM wobble.
- Test low/high sample rates and parameter extremes for finite, bounded output.
- Test preset changes and restart for stale filter state and discontinuities.
- Keep resonators stable, fixed memory and no new per-sample transcendentals on the ESP.
- Software builds/renders do not establish speaker quality or real-device timing. Hardware remains unverified until the identified toy is tested with Luke; do not flash another connected device.
